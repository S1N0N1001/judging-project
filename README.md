# Сервис судейства: запуск и работа

Актуальная версия после доработки от 03.11.2026. Старый файл `документация.txt` описывает прежнюю JSON-версию; используйте эту инструкцию.

## Получение исходников из GitHub

Репозиторий содержит исходники, тесты, ТЗ и журнал разработки. Рабочие базы, коды доступа, виртуальные окружения и готовые EXE не включаются в Git.

После клонирования создайте окружение Python 3.12 x64 и установите requirements.txt (см. раздел «Разработка и сборка»). Запуск исходников: `python launcher.py`. Для Windows-сборки используйте `build.ps1`; стандартный результат — `dist/Judging/Judging.exe`. Упомянутая ниже `dist/LAN_Update` — отдельная локальная поставка обновления, а не каталог, загружаемый из Git.

## Быстрый запуск Windows

1. Откройте актуальную сборку **dist\LAN_Update\Judging\Judging.exe** (перед обновлением остановите старый сервер). Вся папка `Judging`, включая `_internal`, должна оставаться вместе. Для передачи на другой компьютер скопируйте всю эту папку.
2. Дождитесь запуска: браузер откроется автоматически. Если закрылся — нажмите «Открыть интерфейс» в окне лаунчера.
3. При первом запуске задайте пароль секретаря минимум из 12 символов. Секрет первоначальной настройки выдаётся только локальным лаунчером и после создания пароля больше не действует.
4. Дальнейшие открытия адреса без судейского кода показывают вход секретаря. Ссылки из прежнего db.json не дают административного доступа.

Python, OpenServer и интернет для готовой сборки не требуются. Ноутбук остаётся сервером: не выключайте его и не включайте сон во время оценивания. Закрытие браузера не останавливает сервер. Для завершения используйте «Остановить сервер» в лаунчере.

Сборка — без установщика и цифровой подписи. Проверка на независимой чистой Windows 10/11 и репетиция с реальными смартфонами остаются обязательными перед официальным мероприятием.

## Подготовка

- Во вкладке «Настройки» задайте название и явно подтвердите методику. Для новых событий предлагается усечение по каждому критерию при пяти и более отправленных оценках. Прежний алгоритм доступен отдельно для воспроизведения старых результатов.
- Итог округляется half-up до 0,01; равные итоги получают общие места 1, 2, 2, 4. Штрафы, специальные максимумы и исключения из состава жюри не включены автоматически: шкалы и регламент этих случаев ещё требуют согласования.
- Критерии можно обновить загрузкой config.json до открытия мероприятия. После открытия хранится закреплённый снимок; изменение внешнего файла не изменяет текущую методику.
- Добавьте работы и судей. Можно указать участников, тип, стадию, аннотацию и адрес материалов.
- В «Судьи и QR» выберите актуальный Ethernet/Wi-Fi адаптер компьютера; при необходимости используйте ручной ввод адреса и порта, например `http://192.168.137.1:8501`. Не используйте localhost или 0.0.0.0 для телефонов. Если порт занят, лаунчер предлагает другой; этот порт нужно указать и в QR.
- Подключите телефоны к общей сети или точке доступа Windows. В брандмауэре разрешайте входящие соединения только для нужной частной сети. Не отключайте брандмауэр целиком.
- При добавлении судьи сохраните его индивидуальную ссылку или QR: открытый токен не хранится в базе. Потерянную ссылку можно перевыпустить для одного судьи с причиной; старая сразу перестанет работать. Оценки сохраняются за постоянным ID судьи.
- При необходимости сформируйте QR Wi-Fi, введя имя и пароль сети. Сама точка доступа создаётся средствами Windows.

## Импорт прежних данных

В пустом мероприятии откройте раздел импорта, загрузите исходный db.json и запустите импорт. Исходник не изменяется; его точная копия сохраняется в backups. Импорт проверяет диапазоны и полноту карточек; ошибки приводят к отмене всей операции, а не к тихой потере отдельных оценок.

Импорт выполняется один раз. Судьям нужно перевыпустить ссылки. После импорта явно подтвердите алгоритм расчёта. Для соответствия прежней версии сохраняется выбор legacy_total_trim_v1. Точную историческую конфигурацию дескрипторов следует сверить самостоятельно: старый JSON не содержал снимка методики. Числовые оценки при импорте не пересчитываются.

## Оценивание

1. Откройте оценивание в настройках. Затем во вкладке работ назначьте текущую работу кнопкой «Открыть судьям / сделать текущей».
2. Судья видит текущую и ранее открытые работы. Статус обновляется автоматически; список работ — кнопкой «Обновить список работ». Автоматическое переключение не перетирает ввод судьи.
3. Судья выставляет семь баллов. «Не оценено» и 0 различаются. Показаны выбранный дескриптор и все уровни по запросу.
4. «Сохранить черновик» записывает введённые значения; «Отправить и заблокировать» требует всех семи оценок и завершает карточку.
5. Несохранённый ввод хранится только в текущей сессии. При обрыве не закрывайте вкладку; после восстановления повторите сохранение. Полноценная автономная очередь на телефоне пока не реализована.
6. Сохранение из устаревшей вкладки вызывает сообщение о конфликте. Кнопка загрузки сохранённой версии заменяет ввод; прежняя подтверждённая запись не удаляется при начале правки.
7. Секретарь до закрытия видит только статусы. Для исправления отправленной карточки используйте разблокировку с причиной. Судья затем загружает сохранённую версию, исправляет и отправляет заново.

Состав жюри и работ закрепляется после открытия. Удаления оценённых команд и массового сброса оценок нет. В подготовке работу можно архивировать с причиной. Самоотводы, замена человека в составе жюри и закрытие с неполным составом требуют отдельного расширения регламента; текущая версия их не имитирует.

## Итоги и CSV

Закройте оценивание после отправки всех карточек всеми судьями. Откроются числовые итоги, поиск, сортировка столбцов и выгрузки:

- **Сводка CSV** — одна строка на команду/работу: место, итог, критерии и полнота.
- **Оценки судей CSV** — одна строка на пару «работа + судья», исходные баллы всех критериев и комментарий.
- **Расчёт по критериям CSV** — решение по каждой оценке, снятые крайние значения и расхождения.
- **Полный протокол ZIP** — три CSV и metadata.json с исходными данными, методикой и решениями.

CSV по умолчанию предназначен для русских настроек Excel: UTF-8 с BOM, разделитель `;`, десятичная запятая. Если Excel открывает всё одним столбцом, используйте «Данные → Из текста/CSV» и выберите UTF-8 и `;`. Дополнительный профиль использует разделитель запятую и десятичную точку.

Фильтр экрана не ограничивает выгрузку: CSV содержит все работы. Ноль остаётся числом; отсутствующий балл — пустой ячейкой. Текст, похожий на формулу, защищается префиксом апострофа. Секреты доступа не экспортируются.

По legacy-алгоритму детализация использует тот же набор судей, что и итог: крайние снимаются по сумме. Это обеспечивает сверяемость итогового профиля; исходные суммы доступны в scores.csv.

Если включён порог расхождений, до утверждения разберите отмеченные критерии. Решение записывается в поле причины. Утверждение создаёт неизменяемый снимок протокола. Возобновление требует причины и сохраняет прежние снимки в базе, однако UI показывает последнюю актуальную версию.

## Данные, резервирование и восстановление

По умолчанию: `%LOCALAPPDATA%\JudgingApp\`. Внутри находятся data, backups, logs и exports. Скачанные CSV браузер сохраняет в выбранную им папку загрузок. База не хранится внутри EXE и не пропадает при обновлении программы.

Ручной backup доступен в настройках; автоматический создаётся перед изменением состояния, архивированием, восстановлением и сбросом пароля. Копии содержат персональные данные; JSON-копия импорта содержит и прежние секреты. Передавайте их только организаторам. Срок хранения определяет организатор.

Для отдельного каталога данных запустите:

```powershell
.\Judging.exe --data-dir "D:\JudgingData"
```

Для восстановления сначала остановите сервер и закройте лаунчер, затем:

```powershell
.\Judging.exe --restore
```

Выберите SQLite-backup. Рабочая база перед заменой сохраняется отдельно. Для забытого пароля:

```powershell
.\Judging.exe --reset-password
```

Операции выполняются только локально с доступом к учётной записи Windows, не через веб-форму. При нестандартном каталоге добавьте тот же `--data-dir`. Не запускайте два сервера с разными каталогами для одного мероприятия.

## Разработка и сборка

Используется Python 3.12 x64. Закреплённые зависимости находятся в requirements.txt. Пример создания окружения:

```powershell
py -3.12 -m venv .build-venv
.\.build-venv\Scripts\python.exe -m pip install -r requirements.txt
.\.build-venv\Scripts\python.exe launcher.py --data-dir ".\local-data"
```

Проверка и сборка:

```powershell
.\build.ps1
```

Результат: `dist\Judging\Judging.exe` и все его зависимости в соседней `_internal`. Spec включает исходник Streamlit-страницы и config.json, но не реальную базу, старый db.json и коды доступа. Сборка привязана к Windows x64; одиночный onefile пока не является целевой поставкой.

Проверка старта и штатной остановки без браузера:

```powershell
.\Judging.exe --smoke-test --address 127.0.0.1 --data-dir ".\smoke-data"
```

Для режима только на ноутбуке используйте `--address 127.0.0.1`. По умолчанию разрешено подключение по LAN (`0.0.0.0`). Браузер секретаря всегда открывает localhost.

Журнал сервера: logs/server.log; для сборки без консоли также logs/launcher.log. Протоколы тестов и шаги разработки — в SteprMD.


## Обновление: LAN-адреса и удаление судей (03.11.2026)

Обновлённая сборка этой доработки находится в `dist/LAN_Update/Judging/Judging.exe`. Она размещена отдельно, поскольку предыдущий EXE был запущен. Перед использованием обновления остановите прежний сервер штатной кнопкой и закройте его лаунчер; затем запустите новый EXE. Каталог данных по умолчанию прежний, повторный импорт базы не нужен. Если раньше использовали `--data-dir`, передайте тот же путь новой версии. Запуск новой программы при работающей старой откроет прежний сервер по правилам единственного экземпляра.

Вкладка «Судьи и QR» теперь получает IPv4-адреса компьютера, показывает имена адаптеров и использует фактический порт. Выберите адаптер Ethernet/Wi-Fi той сети, где находятся телефоны. Виртуальные/VPN-адреса остаются в списке, но по возможности помещаются ниже обычных адаптеров. Определение адреса не доказывает доступность с конкретного телефона.

DHCP поддерживается: при смене сети или IP нажмите «Обновить сетевые адреса». Если выбранный адрес исчез, будет предложен текущий. Ссылка и QR в интерфейсе строятся заново для выбранного адреса, код судьи не меняется. Ранее распечатанный QR со старым IP сам измениться не может: выдайте новый QR. Для стабильного адреса на протяжении нескольких запусков можно настроить резервирование DHCP на роутере.

Если компьютер получил `172.17.18.194`, а порт сервера 8501, базовый адрес для телефона — `http://172.17.18.194:8501`, индивидуальная ссылка добавляет `/?code=...`. localhost на телефоне обозначает сам телефон, а не ноутбук.

Если ссылка недоступна: сначала откройте базовый адрес на телефоне; проверьте, что сервер запущен в LAN-режиме, оба устройства имеют связь внутри одной сети, брандмауэр разрешает приложение в нужной частной сети, а на точке доступа нет изоляции клиентов/гостевой сети. Брандмауэр целиком отключать не нужно. Наличие Wi-Fi само по себе не гарантирует связь между клиентами сети.

Удаление судьи находится в раскрытой карточке судьи: укажите причину, поставьте подтверждение и нажмите «Удалить судью». Доступно до открытия оценивания. Судья исчезает из действующего состава, его ссылка немедленно отзывается, номер и ID не передаются новому судье. История и прежние записи сохраняются в базе. После начала оценивания изменение состава запрещено, чтобы случайно не пересчитать результаты.
