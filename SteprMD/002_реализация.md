# 002. Хранилище, права, расчёт и интерфейс

Дата: 03.11.2026.

- Добавлены judging_store.py и judging_core.py. SQLite хранит работы, судей с постоянными ID, версии карточек, журнал и утверждённые снимки.
- Все операции записи проверяют актуальные права; сессии секретаря ограничены по времени; токены судей хранятся в виде хешей.
- Первичная настройка выполняется по одноразовому секрету локального лаунчера. Адрес без кода открывает вход.
- Сохранение карточки транзакционное, обнаруживаются конфликты вкладок. Начало правки не удаляет прежние баллы.
- Добавлены состояния мероприятия, блокировка после отправки, разблокировка с причиной, закрытие только при полном составе отправленных карточек.
- Новая методика выбирается и подтверждается явно. Прежний алгоритм доступен для совместимости. Штрафы и специальные максимумы отключены до согласования.
- Исправлены границы критерия 5 для новых конфигураций: 0/5/9/13 вместо 0/5/10/14. Это явное согласование с lik_bez.md; сохранённые исходные баллы не изменяются.
- Добавлены три CSV и ZIP с метаданными. Кириллица: UTF-8 BOM, разделитель по умолчанию точка с запятой; предусмотрен универсальный профиль.
- Исходный main.py сохранён как main_before_changes.py. db.json остаётся нетронутым, миграция запускается отдельно из интерфейса.
- Прежняя техническая документация остаётся историческим описанием; актуальная инструкция будет в README.md.
